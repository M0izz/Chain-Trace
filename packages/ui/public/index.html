        Verification Boundaries & Trust Assumptions

        1. Explain, Don't Decorate

        Every visual status maps directly to a deterministic policy rule (`policy:event-inclusion`, `policy:source-finality`, `policy:message-match`, `policy:destination-execution`). No status is inferred or fabricated on the client.

        2. Truthful State Semantics

        INCONCLUSIVE means evidence is incomplete or pending (e.g. inflight packet), never fraud. REVALIDATION_REQUIRED indicates upstream evidence reorganization without erasing historical facts.

        3. Protocol Assumptions (LayerZero v2)

        Direct RPC receipts on Sepolia and Polygon Amoy are trusted for receipt status and emitted topics. DVN quorum threshold signatures are assumed valid if emitted by EndpointV2.

        4. Append-Only Tamper Evidence

        All state transitions are appended with SHA-256 hash chains (`prev_hash` → `record_hash`). The database prevents updates or deletes of historical audit rows.
